\section*{Problem 2.7: KNN classification across election years}
\subsection*{Problem setup}
The task is to predict each state's election label using obesity percentage as the single input feature. Following the problem specification, I train a KNN classifier using the 2004 data and evaluate it using the 2000 data.

\subsection*{Data and experimental settings}
The supplied election datasets each contain 51 observations: the 50 states and Washington, D.C. Only obesity percentage is used as an input feature. The response is the supplied Democratic (D) or Republican (R) election label. Obesity itself is not the prediction target.

The original data order and supplied labels are preserved, including the 2004 Hawaii label R. All election scores therefore evaluate the supplied labels.

\par\addvspace{6pt}
\noindent\begin{minipage}{\linewidth}
\subsection*{Implementation settings}
The following code specifies the KNN settings used in this experiment. Problem 2.8 uses the same settings with the training and test years reversed.

\begin{lstlisting}[style=pythoncode,caption={KNN configuration used in the experiments.}]
def make_knn(k):
    return KNeighborsClassifier(
        n_neighbors=k,
        weights='uniform',
        metric='euclidean',
        algorithm='brute',
        n_jobs=1
    )
\end{lstlisting}

\subsection*{Why these settings?}
I chose brute-force search because the training dataset contains only 51 observations and one input feature, making direct distance computation practical. Euclidean distance reduces to the absolute difference between two obesity percentages. Uniform voting gives each selected neighbor one vote. The number of neighbors is selected by LOOCV rather than fixed in advance. The setting \texttt{n\_jobs=1} controls parallel jobs for neighbor search; the experiment also uses \texttt{threadpool\_limits(limits=1)} to limit numerical-library threads.
\end{minipage}\par\addvspace{6pt}

\subsection*{Selecting the number of neighbors by LOOCV}
As required by the problem, I select $k$ using leave-one-out cross-validation on the 2004 training data. For each candidate $k$, I hold out one observation, fit the classifier using the other 50 observations, and predict the omitted label. Repeating this for all 51 observations gives one held-out prediction for every training observation.

I evaluate all $k=1,\ldots,50$, including both odd and even values. The maximum is 50 because each LOO fit contains only 50 training observations. No observation from the 2000 test set is used to select $k$. Using 50 observations in each fit retains most of this small training sample, although LOOCV does not guarantee that the selected model will transfer well to another year.

The following code shows how held-out predictions and errors are calculated for each candidate $k$. Here \texttt{x} contains the 2004 obesity percentages, \texttt{y} contains their election labels, and \texttt{rows} collects the validation scores. Numerical-library threads are limited to one during this procedure.
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={LOOCV predictions and error calculation for each candidate k.}]
for k in range(1, len(y)):
    predictions = np.empty(len(y), dtype=y.dtype)
    for train, validation in LeaveOneOut().split(x):
        model = make_knn(k).fit(x[train], y[train])
        predictions[validation] = model.predict(x[validation])
    wrong = predictions != y
    rows.append({
        'k': k,
        'wrong_count': int(wrong.sum()),
        'loocv_error': float(wrong.mean())
    })
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}

The Boolean array \texttt{wrong} records the 0--1 loss: an incorrect label contributes 1, and a correct label contributes 0. Taking its mean gives the resampling error:
\begin{equation}
\widehat R_{\mathrm{LOO}}(k)=\frac{1}{51}\sum_{i=1}^{51}
\mathbf 1\!\left\{\widehat y_{-i,k}(x_i)\ne y_i\right\}.
\end{equation}
Here $\widehat y_{-i,k}$ denotes the classifier fitted without observation $i$. I select the smallest $k$ attaining the minimum error, as detailed below.


\subsection*{Tie handling}
Three distinct types of ties are handled as follows:
\begin{enumerate}
\item \textbf{Equal class votes.} With uniform voting, D and R can receive the same number of votes when $k$ is even. The current scikit-learn classifier resolves this tie in favor of the first class in its sorted class order. For the labels used here, \texttt{classes\_} is \texttt{['D', 'R']}, so a vote tie predicts D. This is a software convention, not an assumption that D is more likely. With two classes, odd $k$ avoids a class-vote tie, but it does not eliminate equal-distance ties.

\item \textbf{Equal neighbor distances.} Equal distances within the selected set do not change a uniform vote if set membership is unchanged. The important boundary case occurs when the $k$th and $(k+1)$th candidate neighbors are equally distant and have different labels: selecting a different boundary point can change the prediction. My code does not implement a secondary rule such as preferring D or the smallest row index. It uses the neighbor set returned by scikit-learn's brute-force implementation. I preserve the original input order and fix the search backend and thread settings. The reported results use scikit-learn 1.9.1; the software version, input order, backend and thread settings specify the experimental conditions. This does not guarantee that the earliest input row is always selected, or that another backend or software version selects the same tied neighbors.\footnote{The scikit-learn documentation warns that predictions can depend on training-data order when the $k$th and $(k+1)$th neighbors are equally distant and have different labels: \url{https://scikit-learn.org/stable/modules/generated/sklearn.neighbors.KNeighborsClassifier.html}.}

\item \textbf{Equal LOOCV errors for different $k$.} Candidate values are evaluated in ascending order, $k=1,\ldots,50$. The code below returns the first minimum, so the smallest $k$ among the tied candidates is selected. In Problem 2.7, $k=7,20,22$ attain the same minimum error, and this rule selects $k=7$.

Beyond providing a reproducible convention, this rule expresses a preference for more local decisions when the observed validation errors are identical. Compared with $k=20$ or $22$, $k=7$ bases each prediction on a smaller neighborhood and retains greater sensitivity to local variation. Larger neighborhoods generally smooth decision boundaries and, when sufficiently broad, can be dominated by the overall majority class, which is R in the 2004 training data. However, equal aggregate LOOCV errors do not demonstrate that the larger candidates actually over-smooth local patterns, and smaller neighborhoods can be more sensitive to noise and distance ties. Thus, choosing the smallest tied $k$ preserves a more local decision rule without claiming lower true prediction risk or general superiority over larger $k$.

\end{enumerate}

\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Excerpt implementing the tie rule for selecting k.}]
best_position = table['loocv_error'].to_numpy().argmin()
return int(table['k'].to_numpy()[best_position]), table, pd.DataFrame(audit)
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}

\section*{Problem 2.11: Regression and model selection}
\subsection*{Problem setup and data}
This problem compares trigonometric and algebraic polynomial regression. For each family, I fit the coefficients at each candidate order and use the analytic Schwartz criterion to select the order. I then consider whether these selection scores alone establish which family predicts better.

I generate ten observations according to the specified data-generating process:
\begin{equation}
x_i\sim\mathcal U(0,1),\qquad
y_i=x_i^2+0.1x_i+\varepsilon_i,\qquad
\varepsilon_i\sim\mathcal N(0,0.5^2).
\end{equation}
The noise variance is $0.25$, so the standard deviation passed to NumPy is $0.5$. The following code fixes the random seed at 42 so that the sample can be reproduced. Both model families use exactly these same observations.

\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Generating the ten regression observations.}]
rng = np.random.default_rng(42)
x = rng.uniform(0, 1, 10)
noise = rng.normal(0, 0.5, 10)
y = x**2 + 0.1*x + noise
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}

This is a newly generated sample from the specified process, rather than the exact observations in the textbook example. The generating curve is shown in the figures for interpretation; it is not used to estimate coefficients or select the order.

\subsection*{Model families and basis construction}
Following the problem definition, I use the cosine-only trigonometric basis and the algebraic power basis:
\begin{align}
f_m^{\mathrm{cos}}(x)&=w_0+\sum_{j=1}^{m}w_j\cos(2\pi jx),\\
f_m^{\mathrm{alg}}(x)&=\sum_{j=0}^{m}w_jx^j.
\end{align}
In the algebraic family, $m$ is the highest polynomial degree. In the cosine family, $m$ is the maximum frequency index. Each family has $m+1$ fitted coefficients, including the constant. At $m=0$, both reduce to a constant model. The label \texttt{'trigonometric'} in the code refers to the cosine-only family above.

The design matrix contains one row for each observation and one column for each basis function. The core construction is:
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Constructing the cosine or algebraic design matrix.}]
def design_matrix(x, m, family):
    x = np.asarray(x, dtype=float).reshape(-1)
    if family == 'trigonometric':
        return np.column_stack([
            np.ones(len(x)),
            np.cos(2*np.pi*x[:, None]*np.arange(1, m+1))
        ])
    if family == 'algebraic':
        return np.vander(x, N=m+1, increasing=True)
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}
For example, at $m=2$, the algebraic basis is $1$, $x$, and $x^2$; the cosine basis is $1$, $\cos(2\pi x)$, and $\cos(4\pi x)$. Neither family includes sine terms.

\subsection*{Least-squares fitting and implementation choice}
For a fixed family and order, the coefficients are estimated by ordinary least squares:
\begin{equation}
\widehat{\boldsymbol w}_m
=\arg\min_{\boldsymbol w}\|\boldsymbol y-A_m\boldsymbol w\|_2^2,
\qquad \widehat{\boldsymbol y}=A_m\widehat{\boldsymbol w}_m.
\end{equation}
Although the basis functions can be nonlinear in $x$, the model is linear in its coefficients. The numerical fitting step is:
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Least-squares estimation for a fixed family and order.}]
a = design_matrix(x, m, family)
coefficients, _, rank, singular = np.linalg.lstsq(a, y, rcond=None)
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}
Using \texttt{lstsq} avoids explicitly computing $(A_m^TA_m)^{-1}$. This is useful because high-order power-basis matrices can be poorly conditioned. The returned rank and singular values provide numerical diagnostics. No ridge or lasso penalty is added; the model order is controlled by the Schwartz criterion.

\subsection*{Order selection and tie rule}
The empirical risk is the training mean squared error, and the degrees of freedom count the fitted coefficients:
\begin{align}
R_{\mathrm{emp}}(m)&=\frac1n\sum_{i=1}^n[y_i-\widehat f_m(x_i)]^2,\\
\mathrm{DoF}&=m+1,\qquad p=\frac{m+1}{n},\\
R_{\mathrm{SC}}(m)&=\left(1+\frac{p\ln n}{1-p}\right)R_{\mathrm{emp}}(m).
\end{align}
I use this course-specific multiplicative Schwartz formula. Its numerical calculation is:
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Computing the analytic Schwartz score.}]
p = dof / n
score = (1 + p*np.log(n)/(1-p))*training_mse
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}
The condition $\mathrm{DoF}<n$ keeps the denominator positive. With $n=10$, I therefore search $m=0,\ldots,8$. I fit every candidate and select the minimum score separately for each family. The following code presents the core search, with numerical diagnostics omitted from the displayed table:
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Fitting candidate orders and selecting the minimum Schwartz score.}]
n = len(x)
models, rows = [], []
for m in range(n-1):
    model = fit_polynomial(x, y, m, family)
    mse = float(np.mean((np.asarray(y)-model.predict(x))**2))
    rows.append({
        'm': m,
        'schwartz_criterion': schwartz(mse, m+1, n)
    })
    models.append(model)
table = pd.DataFrame(rows)
best = int(np.argmin(table.schwartz_criterion.to_numpy()))
selected_model = models[best]
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}
Here \texttt{fit\_polynomial} performs the least-squares fit described above, \texttt{model.predict(x)} evaluates the fitted basis expansion, and \texttt{schwartz} computes the displayed criterion. Candidate orders are evaluated in ascending order, and \texttt{argmin} returns the first minimum. Exact score ties therefore favor the smaller $m$. The comparison uses the computed scores without an additional near-tie tolerance.

\subsection*{Discussion and answer to the comparison question}
The true generating function is quadratic, but the selected algebraic model has $m=1$. The following comparison explains why:
\begin{center}\begin{tabular}{crr}
\toprule
Algebraic $m$ & Training MSE & Schwartz score\\\midrule
1 & 0.08084 & \textbf{0.12738}\\
2 & 0.07822 & 0.15541\\\bottomrule
\end{tabular}\end{center}
Adding the quadratic term slightly reduces training error, but the larger complexity multiplier raises the score. With only ten noisy observations, the criterion need not recover the generating polynomial's degree.

The cosine family also has a structural restriction. For every integer $j$,
$\cos(2\pi j(1-x))=\cos(2\pi jx)$, so every cosine fit satisfies $f(x)=f(1-x)$. The generating function $x^2+0.1x$ does not have this symmetry. Increasing $m$ adds flexibility within this restricted family, but does not remove the restriction.

\textbf{Can the best predictive family be determined from model-selection results alone?} The smaller full-sample Schwartz score favors the algebraic fit under this criterion. It provides an analytic basis for a preference, but it does not establish that the algebraic method has lower prediction error on unseen observations. Both scores are computed from the same fitting sample, and neither is an observed test error. Problem 2.12 therefore compares the complete fitting-and-selection procedures using held-out observations.



\section*{Problem 2.12: Five-fold evaluation of the regression methods}
\subsection*{Data and validation settings}
I reuse the same ten observations from Problem 2.11. As required by the problem, I compare the prediction errors of the two regression methods using five-fold cross-validation, while retaining the Schwartz criterion for order selection.

The fold assignment is generated once and shared by both families:
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Creating one shared set of five validation folds.}]
folds = list(KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
).split(x))
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}
Five folds give eight training observations and two validation observations in each round. Shuffling forms the folds from a permutation of the sample order, and \texttt{random\_state=42} fixes that permutation. Sharing the folds makes the two methods' errors comparable on the same held-out observations. The fold seed is separate from the seed used to generate the data, even though both are set to 42.

\subsection*{Fit and select the order within each training fold}
For each fold and each family, I fit candidate models using only the eight training observations, select $m$ using their training-only Schwartz scores, and then predict the two validation observations. The training size in the criterion is now $n=8$, rather than 10. The condition $m+1<8$ gives the search range $m=0,\ldots,6$.

The following excerpt shows the essential calculation; recording and plotting commands are omitted:
\par\addvspace{4pt}
\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[style=pythoncode,caption={Selecting the order inside each training fold before predicting validation responses.}]
for fold, (train, validation) in enumerate(folds, 1):
    for family in FAMILIES:
        model, selection = select_polynomial(
            x[train], y[train], family
        )
        predicted = model.predict(x[validation])
        mse = float(np.mean((y[validation]-predicted)**2))
\end{lstlisting}
\end{minipage}\par\addvspace{4pt}
Here \texttt{FAMILIES} contains the cosine and algebraic families. The selection procedure fits all allowed orders and returns the model with the smallest Schwartz score, using the same exact-tie rule as in Problem 2.11. It receives only \texttt{x[train]} and \texttt{y[train]}. The validation responses are used only to calculate the final error for that fold. The full-sample orders from Problem 2.11 are not reused.

For validation set $V_r$ and training set $T_r$, the fold error and mean cross-validation error are
\begin{equation}
\mathrm{MSE}_r=\frac12\sum_{i\in V_r}
\bigl[y_i-\widehat f_{T_r}(x_i)\bigr]^2,
\qquad \mathrm{CV\ MSE}=\frac15\sum_{r=1}^{5}\mathrm{MSE}_r.
\end{equation}
Each observation is predicted once by a model fitted and selected without that observation. Since all five validation sets have size two, the mean fold MSE equals the MSE over all ten out-of-fold predictions. These errors evaluate the full fitting-and-order-selection procedure with eight training observations per fit.


\subsection*{Results}
\begin{center}\begin{tabular}{crrrr}

\subsection*{Discussion}
The cosine procedure has the lower mean validation MSE in this particular split. The very large algebraic mean is dominated by fold 2, where the training-only criterion selects $m=6$, with seven fitted coefficients and only eight training observations.

The training inputs in that fold range from approximately $0.09418$ to $0.85860$. One held-out input, $x=0.97562$, lies beyond this range. The selected algebraic model predicts $44.03538$ at this point, while the observed response is $0.61975$. Its other held-out prediction is approximately $0.51596$ for an observed response of $1.11610$. These two errors give
\[
\mathrm{MSE}_2^{\mathrm{alg}}
\approx\frac{(44.03538-0.61975)^2+(0.51596-1.11610)^2}{2}
=942.64.
\]
This is an example of a high-order fit extrapolating poorly beyond its training-input range. The selected design matrix has full column rank, but its condition number is approximately $5.31\times10^5$, indicating numerical sensitivity. Using a least-squares solver that avoids explicit matrix inversion does not prevent a flexible model from making extreme held-out predictions. The training criterion penalizes complexity, but it does not guarantee reliable predictions for every small training sample.

The cosine method selects the constant model in four folds and $m=5$ in one fold. In folds 4 and 5, both families select $m=0$ and therefore produce identical predictions and errors within each fold. The larger algebraic mean should be reported with its fold-level results so that its dependence on one extreme fold is visible.

The sample standard deviation across folds describes the spread of the five fold errors; it is not a confidence interval or the standard error of the mean. With only ten observations, two validation observations per fold, and one fixed split, the comparison is sensitive to which observations are held out. The result supports the cosine procedure for this experiment, but does not establish that it is universally better.

\textbf{Relation to Problem 2.11.} The full-sample Schwartz criterion favors the algebraic family, whereas held-out MSE in this five-fold evaluation favors the cosine procedure. The first comparison uses an analytic selection score on all ten observations; the second measures held-out errors after fitting and selecting on eight observations. They answer different questions, and the difference illustrates why the model-selection scores alone do not settle the predictive comparison.
